Still strong

What is working

  • The review gate finds what nothing else does. OIDC CSRF state and stored XSS in uven, a cross-tenant FK guard in sepanel, an auth rate-limit bypass and an OOM vector in nettobrand, a data race and an orphaned Chrome process in dikta. It also repaired a shipping fallback a verify fix had broken the same day.git-evidence.md § top 10 · retro-evidence.md § 2.4
  • Verifier fixes are the cleanest fixes in the history. When it fires, 4 of 5 fixes are behavioral. Sparkle delegate wiring and appcast overwrite in dikta, the WKWebView getUserMedia hang, email enumeration in uven.git-evidence.md § overall
  • Local validation catches integration bugs where it runs the real service: two uven events that never reached a recipient, green in tests, verifier and gate.retro-evidence.md § 2.5
  • Retro surfaces tooling bugs that got fixed. Worktree base cut at launch HEAD, waves shape mismatch, empty timing data across 7 runs. Each led to a takt commit.retro-evidence.md § 2.6
  • The roster model is sound. Sonnet workers rarely block; defects surface downstream where a stronger model reads the diff. No Revert commit undoes any gate fix.git-evidence.md

Where value leaks

  • The loop files are written but never read by the next agent. bugs.json and review-comments.json are the intended handoff, yet fix workers get a subset inline and cycle 2 reviews cold. The 11 should-fix items from the shadow run reached no agent and no human before cleanup deleted them.see The artifact bus below
  • The verifier asserts without reading. "Verifier hallucinates findings" carried 16 sprints in uven. Two parakeet cycles burned on an unregistered test file and a stale doc line. Windows sprint 4 failed 14/15 on a stale index, passed 15/15 when told to read files. verifier.md unchanged since April.retro-evidence.md § 2.3
  • Hidden scenarios are not independent. /sprint writes them in the same context, right after the acceptance criteria. So verification finds test gaps, not design bugs.sprint.md:482 vs :490-535
  • The gate checklist is web-shaped. SQL injection, NODE_ENV, DB transactions, load simulation, run against a Swift menu-bar app. The per-project hook exists and no repo uses it.final-gate.md · .takt/final-gate-checklist.md
  • Retro carries what it cannot resolve. 23×, 18×, 14× carries. The "chronic after 5" tier changed nothing. Items closed only when you scoped a sprint to them by hand.retro-evidence.md § 3
  • One blocking question inside an unattended run. Local validation ends in AskUserQuestion every time.run.md:131-152

The artifact bus

takt's files are not for a human. They hand work from one context window to the next. So the test is: is the intended reader told to read the file, and what survives the hop? Traced through every prompt builder and every lib/*.md.

.takt/scenarios.json
works
/sprint to verifier. Verifier is told to read it. Hidden from workers as designed.
workbooks
works
worker to merge agent and retro. Both read it. Only gap: the heavy retry gets a one-line reason, not attempt 1's workbook.
validation-report, session.json, stats.json, retro.md, sprint.json
works
Orchestrator, retro, next run. Each reader is pointed at the file.
bugs.json
not read
verifier to fix workers and verifier cycle 2. Fix workers get the same four fields inline from the structured output. Cycle 2's prompt never mentions cycle 1's file, so it re-verifies everything cold.
Lost: cycle memory. Parakeet re-opened BUG-001 twice on new false positives because cycle 2 had no record of cycle 1.
review-comments.json
not read
gate to fix workers and gate cycle 2. Fix workers get id, pass, file, description. line, evidence, impact stay in the file. Cycle 2 reviews cold. Suggestions are in neither the schema nor any prompt, and Phase 7 deletes the file.
Lost: evidence for the fixer, every should-fix suggestion, cycle memory. Shadow MF-1 cycle 2 invalidated cycle 1's fix.
tasks/feature-*.md
never boards
/feature to /sprint only. Worker gets the story JSON. Gate gets the diff and CLAUDE.md. Retro archives the doc.
Lost: the why, scope edges, "what we are not building". The gate cannot check spec compliance because it is never given the spec.
The pattern. Every hop with one channel works. The two loop hops have two channels, file and structured output, and the prompts wire only the narrower one. The producer writes the full record to disk; the consumer receives a summary. Rule to adopt: one channel per hop. For the loops the file should be the channel, since it carries history across cycles and full evidence without growing the orchestrator's context. That is P10.

Suggested order. P9 and P8 today. P10a-d next: largest value for the least code, and it removes the cause of both documented cycle-2 regressions. P6 before P4 so the gate change can be measured. P1 and P3a/b after that. P4, P7, P3c and P10e after two runs of data.

Not proposed: merging the verifier into the gate. The two find different defect classes (spec conformance vs runtime and security), and fixing the verifier's read-before-assert gap is cheaper than losing it.
