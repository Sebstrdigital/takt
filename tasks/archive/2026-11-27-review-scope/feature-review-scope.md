# Feature: Review scope lines + gate fixes from run 1

## Goal

1. Fix the four real defects the first Codex gate found on
   `takt/review-lenses-devops` (MF-016, MF-015, MF-014, MF-012).
2. Give every takt sprint explicit scope lines (in scope, out of scope, real
   environment) and make the gate and verifier judge only inside them, so
   reviews stop blocking on scope creep.

## Scope

**In scope**
- `lib/takt-run.js`: gate verdict consistency (MF-016); a malformed or missing
  stories arg is an error, not a verify-only rerun (MF-014).
- `CLAUDE.md` (takt repo): name the current gate reviewer (MF-015).
- `lib/run.md`: Phase 0 stops when the preflight exits without usable JSON
  (MF-012).
- `lib/final-gate.md`: `basis` on every must-fix, a `follow_ups` list, re-review
  cycles check only fixes and fix-changed lines; read the sprint's scope.
- `commands/feature.md`, `commands/sprint.md`: mandatory Scope section
  (in / out / environment) in Feature docs, copied into `sprint.json` as a
  top-level `scope` object.
- `agents/verifier.md`: a bug is only a scenario that fails; anything else is
  a follow-up note, never a bug.

**Out of scope**
- The scope-creep findings from run 1 (MF-001, MF-004, MF-011, MF-013,
  MF-017, SF-001). They are follow-up ideas, not planned.
- Changes to agent-tools (review-lenses.md 1.1.0 and skeptic 2.2.0 are
  already done and installed).
- Anything under `~/.claude/`; the session agent installs after the run.
- `/spec`, `/epic`, `/takt` commands, unless a story's criteria name them.

**Environment (what "real use" means for this project)**
- macOS (arm64) dev machine, bash/zsh, Claude Code with the Workflow tool.
- GitHub via SSH remotes (`git@github.com:`), accounts `Sebstrdigital`
  (default) and `sebstr-dg` (degaming-wrapper only). No GitHub Enterprise.
- Munin at munin.local, validation VM at validation.local (`ssh validation`),
  Codex CLI with gpt-6.2-sol.

## Context

- Run 1 branch: `takt/review-lenses-devops` (draft PR). This sprint stacks on
  it.
- Run 1 review findings (for workers fixing MF-*):
  - MF-016 lib/takt-run.js:635 — the Workflow accepts a PASSED gate result that
    also reports open must-fix ids.
  - MF-015 CLAUDE.md:42 — project instructions still prescribe the obsolete
    gate reviewer.
  - MF-014 lib/run.md:111 / lib/takt-run.js:47 — a missing, non-array or
    malformed stories arg is treated as an intentional verify-and-gate rerun.
  - MF-012 lib/run.md:24 — Phase 0 has no stop/report branch when
    devops-checks.sh exits before producing check results (non-JSON output,
    exit code 2).

## Decisions

- A verify-only rerun is explicit: `args.verifyOnly === true` with an empty
  stories array. Missing or non-array stories → throw. Empty array without
  verifyOnly → throw.
- The gate result is PASSED only when the verdict says PASSED AND
  `openMustFixIds` is empty; any disagreement is treated as BLOCKED and logged.
- `sprint.json.scope = { in: [..], out: [..], environment: [..] }` (string
  arrays). The gate and verifier get it via the sprint.json path they already
  receive.
- Reviewers may still propose follow-ups; they go in `follow_ups` and never
  block or reach a fix worker.
